# Перевірка версії 2.1.0 — 10.10.2026

Файли: `gemini-code-1791630357495.json`, `gemini-code-1791630351234.js`. Перевірено локальний контрактний архів SQLite, CSV, довідник сутностей і браузерні архіви КАД. Надані файли не змінено. Віддалений PostgreSQL і зовнішні документи повторно не перевірялися.

## Підтверджено

Усі порівнювані загальні агрегати, розподіли за роками й валютами збігаються з аудитом проєкту. SHA-256 CSV збігається з указаним у JSON та попереднім прямим перерахунком. Підрахунок судових архівів також збігається: 47 старих, 500 браузерних рядків, 499 унікальних браузерних справ, 546 унікальних разом.

Чотири сутності з `russian_defence_entities.json` мають ті самі назви, ІПН та списки документальних URL, що й локальний довідник. Усі шість ІПН проходять контрольну суму. Tier, TTR, TTS та графові метрики залишені null. Непідтверджені Радуга й Елпа вилучені.

## Фактичні помилки в JSON

| Підприємство | ІПН | single_party_customer_records у JSON | У локальній SQLite |
|---|---|---:|---:|
| КТРВ | 5099000013 | 0 | **4** |
| Воткинский завод | 1828020110 | 0 | **1** |
| ОЕЗ Алабуга | 1646019914 | 0 | **20** |

Усі числа таблиці додатково перевірено безпосередньо за CSV: результат збігається зі SQLite. Для ВНІІР-Прогрес 0, Базальту 1 та Темп-Авіа 5 односторонніх записів підтверджуються. Для всіх шести сутностей двосторонніх контрактних записів у цьому архіві — 0. Це обмеження локального архіву, а не доказ відсутності договорів у реальному світі.

Для Базальту й Темп-Авіа `browser_search_records: 0` некоректно описує непроведений окремий пошук. Потрібно `null` та `search_status: not_performed`; нуль означав би виконаний пошук без результатів.

Назва Темп-Авіа в архіві містить правову форму ПАО. Якщо `company_name` має бути юридично точною назвою, слід відтворити її з експорту або окремо позначити коротку відображувану назву.

## Помилки й обмеження JSX

- На рядку 47 та в методологічній вкладці відсутні агрегати підміняються статичними числами через `||`. Потрібно показувати «немає даних», а не старий підрахунок.
- `meta.missing_price_rub || 3` перетворює реальний нуль на 3. Аналогічно для судових справ нуль може бути замінено на 546. Перевірено поведінку виразів JavaScript.
- `graph_metrics?.v_eff_latora !== null` пропускає undefined у числову гілку: відсутній об'єкт може спричинити помилку, відсутнє поле — NaN. SSR має той самий дефект. Потрібна перевірка на null та undefined, а для чисел — скінченність.
- Підрахунки контрактів із відсутніми полями відображаються як 0 через `?? 0`; це також плутає невідомий стан із перевіреним нулем.
- Статус graph_metrics_computed=false, TTS/TTR null і шлях CSV досі задані текстом. Поточному JSON це відповідає, але після оновлення даних інтерфейс може показувати неправильний статус.
- `bilateral_verified_pairs` змішує наявність ІПН обох сторін, унікальні пари та документальну верифікацію. Для підрахунку записів краще `contracts_with_both_identifiers`.

## Походження атрибутів

Для Базальту та Темп-Авіа поля джерел містять словесні описи замість точних шляхів і номерів записів. Наявність назви у companies.csv не доводить оборонну спеціалізацію, тому тексти у defence_designation_sources не є достатнім доказом. Відповідність офіційних URL локальному довіднику підтверджено, але актуальність і зміст зовнішніх сторінок у цьому аудиті не перевірялися.

Повний машинний результат, хеші та докази підрахунків: [observations.json](observations.json).
