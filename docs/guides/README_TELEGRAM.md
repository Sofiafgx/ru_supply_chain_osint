# Парсер Telegram

Збирає всю історію повідомлень, яку Telegram дозволяє читати вашому акаунту,
для **32 адрес** з `config/telegram_channels.txt`. Наявний `main.py` продовжує працювати
окремо. Парсер не надсилає повідомлень і не приєднується до груп чи каналів.

## Збір без входу в Telegram

Доступний окремий режим публічних сторінок `t.me/s`:

```sh
.venv/bin/python src/telegram_public_cli.py
```

Цей режим не потребує номера, API ID, коду входу чи сесії. Він послідовно
перевіряє всі 32 початкові адреси та рухається до старіших сторінок по посиланнях Telegram.
Також читає `config/telegram_channels_related.txt`: там збережені канали, підтверджені
офіційними профілями/сайтами відповідних джерел. Початкові адреси не замінюються:
наприклад, профіль групи `@fighter_bomber` прямо посилається на канал `@bomber_fighter`,
офіційний прескіт Molfar — на `@molfar_global`, а медіакіт Опендатабота —
на `@OpendatabotChannel`. Додаткові канали перевіряються першими.
Результати: `data/telegram_public/archive.sqlite3`, `posts.jsonl`, `data/imports/posts.csv`
та `progress.json`. Експорт оновлюється під час збору; для великих архівів
інтервал зростає. Повторний запуск використовує збережені курсори та перевіряє
нові пости. SIGTERM/Ctrl+C зберігають результати й завершують процес.

**Це архів доступних вебпрев'ю.** Telegram може не показувати весь текст,
частину медіа або старі пости без входу. Такі обмеження неможливо подолати цим
режимом. Для недоступних адрес записується `web_preview_unavailable`;
`web_history_exhausted` означає, що закінчилась пагінація вебпрев'ю, і не є
гарантією повного архіву каналу. Реакції та точні лічильники у цьому режимі
недоступні. Зберігаються текст, HTML тексту, дата, URL, відображений лічильник
переглядів, посилання на доступні медіапрев'ю й попередження вебсторінки.
Медіафайли автоматично не завантажуються. Вебархів зберігається окремо від API-архіву.

Для цього режиму додатково потрібні `httpx` та `beautifulsoup4` із `requirements.txt`.
Запущене фонове завдання записує журнал у `data/telegram_public/collector.log`,
а PID — у `data/telegram_public/job.json`. Зупиняти потрібно лише процес із
цього файла, звіривши, що це `src/telegram_public_cli.py`.
При тимчасових мережевих помилках (`network_retry`) збір не завершується:
програма чекає 60–300 секунд і повторює запит зі збереженого місця.
Недоступність прев'ю (`web_preview_unavailable`) не є доказом видалення каналу.
`config/telegram_channels_priority.txt` задає порядок перевірки вже заданих адрес;
пріоритет не видаляє решту джерел. `channel_coverage.csv` автоматично оновлюється
разом з експортом і показує кількість постів, найстаріший ID/дату та перевірену
межу історії. Досягнення ID 1 або останньої вебсторінки не підтверджує дату
створення каналу чи наявність видалених/прихованих постів. Поле
`complete_since_creation_verified` у `progress.json` залишається `false`.
Під час експорту також автоматично оновлюються окремі файли `<username>.csv`
для кожного джерела зі зібраними постами. Вони містять увесь поточний локальний
архів цього каналу, а не лише приклади. Поки триває завантаження старіших
сторінок, ці файли теж є неповними; стан видно в `channel_coverage.csv`.

## Встановлення і перший запуск

Потрібен Python 3.9 або новіший. Виконайте в папці проєкту:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install 'Telethon>=1.45.0,<2.0' 'python-dotenv>=1.0.0'
```

Ці дві залежності достатні для Telegram-парсера. Для решти проєкту можна
встановити весь `requirements.txt`.

Отримайте власні `api_id` та `api_hash` на [my.telegram.org/apps](https://my.telegram.org/apps)
за [офіційною інструкцією Telegram](https://core.telegram.org/api/obtaining_api_id).
Додайте до наявного `.env` поля з `.env.example`:

```dotenv
TELEGRAM_API_ID=ваш_числовий_id
TELEGRAM_API_HASH=ваш_api_hash
TELEGRAM_SESSION=data/telegram/account
```

`TELEGRAM_PHONE` необов'язковий: без нього програма запитає номер під час входу.
Перший запуск попросить номер, код Telegram і пароль 2FA, якщо він увімкнений.
Вводьте їх у локальному терміналі. BotFather-токен для читання історії не підходить.
Файл сесії зберігає доступ до акаунту; не передавайте його іншим.
`.env`, сесії та результати виключені з Git через `.gitignore`.

```sh
python src/telegram_cli.py sources
python src/telegram_cli.py collect --export-format jsonl
```

За замовчуванням немає ліміту повідомлень. Історія читається від найстаріших
повідомлень до найновіших, із паузою між запитами. Telegram може вимагати довшу
паузу: програма показує час очікування й продовжує автоматично.
Великий архів може збиратися багато годин.

## Продовження і вкладення

Повторний запуск тієї самої команди продовжує збір із останнього збереженого ID
кожного каналу та додає нові повідомлення. Ctrl+C можна використати для зупинки.
Текст повідомлення й курсор записуються в одній транзакції; ключ
`(channel_id, message_id)` запобігає дублям, зокрема після зміни назви каналу.
Поточний прохід завершується на верхній межі історії, визначеній на його початку;
новіші пости потраплять у наступний запуск.

```sh
# Коротка перевірка: максимум 100 повідомлень на кожне джерело за запуск.
python src/telegram_cli.py collect --limit 100

# Повний доступний архів із фото, відео, аудіо та документами.
python src/telegram_cli.py collect --download-media --export-format jsonl

# Оновити старі тексти/лічильники та додати вкладення до вже зібраних постів.
python src/telegram_cli.py collect --rescan --download-media
```

Без `--download-media` зберігаються опис і метадані вкладень. Якщо додати цей
прапорець пізніше, для старих постів потрібен `--rescan`. Вкладення завантажуються
через тимчасовий файл; невдале завантаження не просуває курсор цього поста.
Під час повторного сканування вже наявні незмінені вкладення використовуються з диска.
Альбоми зберігаються як окремі повідомлення зі спільним `grouped_id`.

## Результати

- `data/telegram/archive.sqlite3` — повідомлення, курсори та стан джерел.
- `data/telegram/posts.jsonl` або `data/imports/posts.csv` — експорт через `--export-format`.
- `data/telegram/media/<channel_id>/` — вкладення, якщо замовлено завантаження.
- `data/telegram/account.session` — локальна сесія Telegram.

Зберігаються ID, назва і username каналу, текст/підпис, час публікації та
редагування, посилання на пост, URL з тексту та прихованих посилань, перегляди,
репости, кількість відповідей, реакції, дані пересилання, метадані вкладення,
шлях до файлу й час збору. JSONL також містить повний об'єкт повідомлення `raw`.
Дати записуються у форматі ISO 8601 із часовим поясом, як їх повертає Telegram.
CSV має UTF-8 BOM для Excel; потенційні формули в текстових клітинках
екрануються апострофом. JSONL зберігає текст без такого екранування.

```sh
python src/telegram_cli.py status
python src/telegram_cli.py export --format csv --output data/telegram/posts.csv
python src/telegram_cli.py export --format jsonl --output data/telegram/posts.jsonl
```

Експорт і перегляд стану працюють без авторизації та мережі. Експорт читає архів
послідовно й замінює вихідний файл лише після успішного завершення.

## Типи джерел та обмеження

Кожна адреса перевіряється через Telegram. Канали й групи підтримуються;
адреси ботів отримують `skipped_bot`, користувачів — `skipped_user`.
Типи адрес зі списку, включно з `@Opendatabot` та `@YouControlBot`, визначаються
під час реального запуску. Парсер не починає діалог із ботами.

Для недоступної/видаленої адреси або іншої помилки записується `error` та
її причина, після чого збір переходить до наступної адреси. Повторний запуск
знову перевіряє такі адреси. `complete` означає, що прохід доступної історії
завершився; `limit_reached` — спрацював `--limit`; `collecting` може залишитися
після переривання. Код виходу: 0 — завершено без помилок джерел (пропущені боти
допустимі), 1 — помилка, 2 — відсутня залежність, 130 — Ctrl+C.

Видалені пости, прихована історія та приватні канали без доступу не можуть бути
відновлені. Для доступних коментарів до архівованих дописів додано окрему
команду `comments` і опцію `collect --collect-comments`. Результати й курсори
коментарів зберігаються окремо від основної історії. Докладніше:
[структурування даних і коментарі](README_TELEGRAM_STRUCTURE.md).
Повторний звичайний запуск не перечитує старі пости: для актуалізації текстів,
переглядів і реакцій використовуйте `--rescan`. Видалені з Telegram повідомлення
залишаються у локальному архіві; парсер не позначає їх видаленими.

Щоб змінити джерела, відредагуйте `config/telegram_channels.txt` (одна адреса на рядок)
або задайте `collect --channels-file шлях/до/списку.txt`. Для окремого архіву є
`--db шлях/до/архіву.sqlite3` у командах `collect`, `export`, `status`.

Технічна основа: [Telethon — iter_messages та download_media](https://docs.telethon.dev/en/stable/modules/client.html).

## Перевірка

```sh
python -m unittest discover -s tests -v
```

Тести працюють без Telegram-акаунта: перевіряють відновлення після помилки,
очікування FloodWait, ізоляцію недоступних джерел, розпізнавання ботів,
експорт, вкладення та оновлення без дублікатів.
