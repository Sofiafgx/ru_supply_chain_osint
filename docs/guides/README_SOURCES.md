# Парсери реєстрів і торговельних джерел

Єдиний запуск: `src/sources_cli.py` або `main.py`. Результати — JSONL з походженням
кожного запису та окремий звіт про відхилені рядки й обмеження. Відсутні суми,
дати, ІПН та HS-коди залишаються `null`. Згадка обладнання у профілі компанії
не створює контракту.

Для відновлюваного збору за періодом, проходження пагінації та PDF C4ADS
використовуйте [колектор і результати](README_COLLECTION.md).
Нижче описано окремі адаптери; їхній `--pages` обмежує кількість сторінок
і не обходить ліміт 500 результатів Госзатрат. Колектор ділить періоди,
зберігає сирі відповіді й має окремий контроль охоплення.

## Джерела та режими

| Джерело / назва в CLI | Що витягується | Режими |
|---|---|---|
| ЄІС / `zakupki` | Реєстровий номер, предмет, ціна, дата, доступні ІПН | `--query`, `--url`, HTML, XML контрактів, JSON/CSV |
| Checko / `checko` | Назва, ІПН, ОГРН, КПП, адреса, статус, дата реєстрації | `--inn` з API-ключем, `--url`, HTML, JSON/CSV |
| Госзатраты / `clearspending` | Контракти, ІПН замовника та всіх постачальників, сума RUB, дата | `--query`, `--url`, JSON/JSONL/CSV, HTML із таблицею або карткою |
| Арбітраж / `kad` | Номер і ID справи, суд, суддя, позивачі, відповідачі, дата | `--query` за учасником, `--url`, HTML результатів пошуку, JSON/CSV |
| ImportGenius / `importgenius` | Відправник, одержувач, накладна, HS, дата, USD, вага, кількість | `--url` публічного профілю, HTML таблиць, CSV/JSON/JSONL із власного доступу |
| Panjiva / `panjiva` | Ті самі поля; також видимий Sample Bill of Lading | `--url` профілю, HTML, CSV/JSON/JSONL |
| 52wmb / `52wmb` | Ті самі поля з англійських, китайських або власних колонок | `--url` доступної таблиці, HTML, CSV/JSON/JSONL |
| C4ADS / `c4ads` | Заголовки, описи, дати за наявності, URL звітів, посилання на файли | `--query` по каталогу, `--url` звіту, HTML, JSON/CSV |

Checko повертає профілі компаній. C4ADS повертає дослідницькі публікації;
у `src/sources_cli.py` посилання на PDF і таблиці зберігаються без обробки їхнього вмісту.
`src/collection_cli.py` додатково завантажує доступні PDF з C4ADS і витягує текст.
HTML торговельних профілів часто містить лише частину історії та приховані поля.
Для повної історії використовуйте вивантаження зі свого облікового запису.

## Запуск

Потрібен Python 3.9+. У наявне середовище вже встановлено залежності нових парсерів.
Для окремого встановлення:

```sh
python3 -m venv .venv
PYTHONPATH=src .venv/bin/python -m pip install 'httpx[socks]>=0.27,<1' 'beautifulsoup4>=4.12,<5' 'lxml>=5.1' 'pydantic>=2.6,<3' 'python-dotenv>=1,<2'
.venv/bin/python src/sources_cli.py --help
```

Приклади онлайн-збору:

```sh
.venv/bin/python main.py clearspending --query 'станок' --pages 2
.venv/bin/python main.py zakupki --query 'микросхема' --pages 1
.venv/bin/python main.py kad --query 'назва учасника справи' --pages 1
.venv/bin/python main.py checko --inn '0012345678'
.venv/bin/python main.py panjiva --url 'https://panjiva.com/S-N/39902277'
.venv/bin/python main.py c4ads --query 'Russia' --pages 6
```

ІПН у прикладі Checko синтетичний: замініть його власним цільовим ІПН.
Для ImportGenius і 52wmb передавайте адресу конкретного профілю/таблиці,
а не головної сторінки. `--query ''` для C4ADS збирає каталог без фільтра;
фільтр шукає підрядок у заголовку й описі на заданій кількості сторінок.

Приклади локальних вивантажень:

```sh
.venv/bin/python main.py zakupki --input exports/contracts.xml
.venv/bin/python main.py checko --input exports/checko.html --source-url 'https://checko.ru/company/адреса-профілю'
.venv/bin/python main.py clearspending --input exports/contracts.json
.venv/bin/python main.py kad --input exports/kad-search.html
.venv/bin/python main.py importgenius --input exports/importgenius.csv
.venv/bin/python main.py panjiva --input exports/panjiva.csv --hs-prefix 8542 --hs-prefix 8457
.venv/bin/python main.py 52wmb --input exports/52wmb.csv --column-map examples/trade_column_map.json
.venv/bin/python main.py c4ads --input exports/c4ads.html --source-url 'https://c4ads.org/reports/'
```

Файли мають бути UTF-8; CSV може мати BOM, кому, крапку з комою або табуляцію.
JSON — масив об'єктів або оболонка `data`, `records`, `items`, `contracts.data`.
Формат визначається розширенням локального файлу; `--format` перевизначає його.
XLSX, ZIP і PDF потрібно попередньо експортувати/розпакувати у підтримуваний формат.
Великі вивантаження діліть на файли: цей CLI обробляє один файл у пам'яті.

## Доступ і актуальні адреси

У `.env` за прикладом `.env.example` задайте `CHECKO_API_KEY` для пошуку Checko
за ІПН. `CLEARSPENDING_API_KEY` потрібний для запитів через
`--url https://newapi.clearspending.ru/csinternalapi/v1/...` з вашої документації.
Ключ додається автоматично, не записується у походження записів і не передається
до публічного вебпошуку. `OSINT_PROXY` або `--proxy` задає один власний проксі.

Пошук Госзатрат використовує поточний публічний запит сайту
`https://clearspending.ru/api/gw/filtered-contracts/`, який перевірено 08.10.2026.
Це внутрішній запит вебінтерфейсу, його стабільність не гарантується.
Старий `openapi.clearspending.ru/restapi/v3` не використовується.
Офіційні сторінки: [API Госзатрат](https://clearspending.ru/docs),
[доступ розробників](https://clearspending.ru/for-developers),
[Checko API](https://checko.ru/integration/api/company),
[каталог C4ADS](https://c4ads.org/category/reports/).

КАД використовує запит `/Kad/SearchInstances`, знайдений у поточному JS самого
сайту. Це не офіційний стабільний API. Для HTML потрібна відповідь пошуку зі
справами; збережена початкова форма КАД їх не містить.
ЄІС парсить видимі картки результатів і XML `contract`; поля, яких немає в
картці, залишаються порожніми. Парсер не завантажує автоматично всі вкладені
документи контракту. Підтримку конкретного XML-вивантаження варто перевірити
перед великим збором: формати ЄІС відрізняються за видом документа.

Клієнт перевіряє TLS, робить паузи між запитами, обмежено повторює мережеві/5xx
помилки та зупиняється на обмеженні доступу. CAPTCHA/антибот-сторінка викликає
явну помилку. Новий CLI не використовує автоматичну ротацію `config/private/proxies.txt`.

Початкові перевірки з цього середовища 08.10.2026 (демонстраційні вибірки):

| Джерело | Перевірений результат |
|---|---|
| Госзатраты | Онлайн-пошук: 25 контрактів, ІПН/ціни/дати прочитані |
| C4ADS | Онлайн-каталог: 9 публікацій на першій сторінці |
| Panjiva | Реальний HTML профілю: 2 видимі записи; частина полів прихована |
| Checko, ЄІС | Прямі запити не відповіли в межах таймауту; локальні парсери перевірено тестами |
| КАД | Повна форма та JS доступні, пошук повернув HTTP 451; парсинг відповіді перевірено тестами |
| 52wmb | HTTP 403; адаптер вивантажень і таблиць перевірено тестами |
| ImportGenius | HTTP 407 у цьому середовищі; публічні заголовки перевірено на сайті, парсер — тестами |

API Checko з реальним ключем і повні платні вивантаження торговельних сервісів
не перевірялися: реквізити/файли не надані.
Актуальний обсяг основного збору — у `data/collection_20261008/REPORT.md`;
він не обмежується цими демонстраційними результатами.

## Результати та інтеграція

За замовчуванням вихід — `data/sources/<source>.jsonl`; інший шлях задає `--output`.
Успішний запуск замінює цей файл. Якщо мережевий запит або парсинг завершується
помилкою, попередній вихідний файл зберігається. Повторний запуск не накопичує
архів: для архівування задавайте окремий шлях для кожного збору.

Поруч створюється `<output>.report.json` з кількістю записів, відхилених рядків
і загальними попередженнями. Запис містить `source`, `record_type`, `record_id`,
`source_url`, `collected_at` (час обробки у UTC), `data` і `warnings`.
Для локального входу також записуються абсолютний `input_file` і SHA-256
початкового файлу. Ідентичні записи видаляються всередині запуску; різні
товарні рядки однієї накладної зберігаються окремо.

Статуси завершення: `0` — отримано записи; `1` — помилка;
`2` — підтверджених записів немає. Причини й попередження видно у звіті.

Вага нетто та брутто зберігаються окремо. Неідентифікований стовпець `Weight`
зберігається у `weight_raw`, без припущення про тип чи одиниці. Загальну
вартість без позначки USD парсер не вважає доларовою. ІПН і HS-коди — рядки,
початкові нулі не втрачаються. Для нестандартних колонок задайте
`--column-map`: канонічне поле → назва вашої колонки. Доступні поля перелічені
у `ALIASES` в `parsers/trade_sources.py`.

`CustomsDataParser.parse_records()` збережений для старих викликів і повертає
`TradeEdge` лише за наявності всіх обов'язкових числових/ідентифікаційних полів.
Неповні нормалізовані записи залишаються у `last_result`.
`RussianProcurementParser.scan_company_contracts()` тепер читає справжні
контракти ЄІС і відкидає записи без підтвердженого ІПН, ціни або дати.

## Дані для TTS

`replenishment_intervals(records, consignee_inn, hs_prefix="8542")` повертає
інтервали між різними днями видимих поставок; за недостатніх даних середнє —
`None`. Потрібен точний ІПН: парсер не ототожнює компанії лише за схожою назвою.

`estimate_tts(stock_units, daily_consumption_units)` обчислює TTS у днях як
запас / добове споживання. Обидва параметри мають бути в однакових одиницях.
Приклад із **умовними**, заданими дослідником числами:

```python
import json
from pathlib import Path
from models.source_records import SourceRecord
from parsers.trade_sources import replenishment_intervals, estimate_tts

records = [SourceRecord.model_validate(json.loads(line))
           for line in Path("data/sources/panjiva.jsonl").read_text().splitlines()]
print(replenishment_intervals(records, "0012345678"))
print(estimate_tts(stock_units=1000, daily_consumption_units=25))  # 40 днів
```

Історія поставок сама по собі не встановлює залишок запасів або добове
споживання. За відсутності цих величин можна звітувати про інтервали,
але не про фактичний TTS.

## Перевірка

```sh
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -p 'test_sources.py' -v
```

Тести не потребують мережі або ключів; використовують синтетичні дані та
перевіряють усі вісім джерел, пропущені поля, початкові нулі, локалізовані числа,
дедуплікацію накладних, відмови доступу, повтор тимчасового збою і збереження
вихідного файлу при помилці. Реальні перевірочні результати цього запуску
збережені окремо в `data/verification/`.
