`python3 src/social_browser_import.py --batch path/to/batch.json --directory data/social_history`

Імпортер працює офлайн із наявним точним індексом `SocialArchive`. Перед першим збором потрібна інвентаризація наявних даних проєкту. Він не відкриває браузер, не читає токени та не змінює API-завдання або `reports/status/coverage.json`.

Формат пакета:

```json
{
  "posts": [{
    "platform": "X",
    "account_handle": "@example",
    "post_id": "123456789",
    "timestamp": "2024-01-02T10:00:00Z",
    "text": "Повний оригінальний текст, прочитаний у DOM допису",
    "url": "https://x.com/example/status/123456789",
    "source_mode": "browser_dom",
    "text_complete": true
  }],
  "observations": [{
    "platform": "X",
    "account_handle": "@example",
    "url": "https://x.com/example",
    "status": "partial_capture",
    "detail": "Переглянуто видиму сторінку; решта історії не перевірена"
  }],
  "checkpoint": {"account_handle": "@example", "next_url": "https://x.com/example", "detail": "Точка для продовження перегляду"}
}
```

Обидва масиви обов’язкові; можуть бути порожніми. `checkpoint` — необов’язковий JSON-об’єкт. Спостереження можуть містити `date_range: {start, end}` із включним початком і виключним кінцем. Статус описує лише побачене, наприклад `partial_capture`, `blocked_login`, `unavailable`, `search_no_results`; повноту історії браузер не підтверджує.

Колектор має розкрити скорочений текст і перевірити оригінал. `text_complete: true` — явне підтвердження колектора, а не автоматична перевірка DOM імпортером. Не передавайте пошукові уривки, текст вкладеного чужого допису замість оригіналу, репости чи здогадки. Відсутню дату публікації не можна замінювати поточним часом: допис слід залишити незбереженим і записати причину в `observations`. Потрібна абсолютна дата з часовим поясом.

Для X permalink має вигляд `https://x.com/HANDLE/status/NUMERIC_ID`; для Threads — `https://www.threads.net/@HANDLE/post/SHORTCODE` або відповідний `threads.com`. Автор та ID повинні збігатися з полями запису. Для Threads браузерний shortcode зберігається як `post_id` у просторі платформи Threads. Відповідність shortcode числовому API ID не встановлюється; майбутній імпорт API зіставляється також за канонічним автором, текстом і датою, але без цих однакових значень відповідність не гарантована.

SHA256 точних байтів пакета забезпечує повторний імпорт без дублювання спостережень або зміщення чекпоінта. Дописи, індекс, спостереження і чекпоінт записуються однією транзакцією. За іншого SHA256 відомі ID та повний канонічний вміст теж відсікаються. Додаткові таблиці: `browser_batches`, `browser_observations`, `browser_checkpoints`.

Результати: `browser_posts.csv`, `browser_posts.jsonl`, `browser_coverage.json`, `BROWSER_REPORT.md`. Експорти містять лише нові унікальні дописи, збережені з `source_mode=browser_dom`; статус кожного акаунта — останнє записане спостереження. Повнота завжди `not_verified`. Експорти можна відновити повторним запуском після збою запису файлів; база лишається джерелом істини.

Продовження виконується через дозволені інструменти браузера у поточній
авторизованій сесії. Читати треба оригінальний текст із DOM, точний `datetime`
і permalink. В X натиснути Show original для автоперекладених дописів;
нерозкритий Show more пропускати з позначкою для повторного читання.
Текст карток посилань і вкладених цитат не підміняє основний текст.
Збережені позиція прокрутки й останній ID допомагають відновленню, але
не є серверним курсором: після перезапуску потрібно повторно відкрити
вікно та пропустити ID зі спільного індексу.
