# Локальна обробка митного експорту

Специфікація полів `importer_inn`, `declaration_date`, `units_qty`, джерел
і пошукових підвибірок для TTS: [docs/guides/README_CUSTOMS_TTS_UK.md](README_CUSTOMS_TTS_UK.md).

`src/local_trade_pipeline.py` працює без мережевих запитів. Вхідні файли:
CSV, JSON-масив, JSONL, XLSX, Parquet або SQLite з явно заданою таблицею.
Архіви, текстові SQL-дампи та інші формати ГТД потребують попереднього
перетворення; назва «дамп ГТД» не визначає формат.

## Налаштування

Конфігурація — `config/local_trade_pipeline.json`, цільові фільтри —
`config/trade_scan_plan.json`. Відносні шляхи обчислюються від папки конфігурації.
`input_file` спочатку порожній: реального митного експорту ще немає.
Укажіть його у конфігурації або через `--input`.

```sh
.venv/bin/python src/local_trade_pipeline.py --input exports/customs.csv
```

`column_map` зіставляє канонічне поле з колонкою вашого експорту. Наприклад:

```json
{
  "importer_tax_id": "ИНН получателя",
  "importer_name": "Получатель",
  "exporter_name": "Отправитель",
  "hs_code": "Код ТН ВЭД",
  "shipment_date": "Дата регистрации декларации"
}
```

Назви колонок тут — приклад, їх потрібно звірити з реальним файлом.
Без `column_map` очікуються канонічні назви. Пропущена зіставлена колонка
викликає помилку. Метадані `source`, `import_country`, `date_type`
повинні бути в колонках або явно задані у `defaults` після перевірки експорту.
Наприклад, тільки для файлу декларацій імпорту RU:

```json
{
  "source": "customs_gtd_dumps",
  "import_country": "RU",
  "date_type": "declaration"
}
```

Дата підтримує YYYY-MM-DD, YYYY/MM/DD і тип дати XLSX/Parquet.
Для митної вартості необхідні `declared_value_usd`, `value_currency: USD`
та `value_type: customs_declared`; автоматичної конвертації валют немає.
Кількість: `quantity_units` або `quantity` з одиницею `pcs`, `pieces`, `шт`, `шт.`.
Вага нетто: `net_weight_kg`. Невизначені одиниці не перетворюються.

CSV читається з UTF-8/BOM і збереженням переносів рядків у клітинках;
роздільник задається `csv_delimiter`. Для XLSX можна задати `sheet`,
інакше використовується активний аркуш. Заголовок — перший рядок.
Для SQLite необхідне `sqlite_table`; підключення лише для читання.
ІПН і HS у вихідному експорті слід зберігати текстом: втрачені нулі
в числових клітинках не відновлюються припущеннями.

## Ідентифікація отримувача

Довідник: `database/employers_2026-10-09.csv`, колонки `name`, `inn`.
Якщо ІПН заданий, він перевіряється; неправильний ІПН не замінюється
автоматично результатом пошуку за назвою.

Якщо ІПН відсутній, назва нормалізується: Unicode NFKC, регістр,
ё/е, лапки/пунктуація/пробіли та початкова скорочена правова форма.
Назви філій, міст і суттєві слова не видаляються. Зіставлення дозволене
лише за точним збігом нормалізованої назви з одним валідним ІПН у всьому
довіднику. Два різні ІПН, порожній або неправильний ІПН у збігах —
неоднозначність, яка залишається в аудиті. Нечіткого пошуку немає.

Отриманий із назви ІПН є висновком за довідником, а не полем митної
декларації. Аудит зберігає початковий рядок, нормалізовану назву,
кандидатів із довідника, їхній `match_method` і метод визначення ІПН.
Надійність такого висновку залежить від точності самого довідника.

Цільові ІПН «Алабуги» та Воткінського заводу оновлено на 1646019914
і 1828020110 за уточненням користувача. Початкові номери залишено
в `requested_importer_inns_before_correction` та `identity_corrections`.
ІПН 1804002498 не має правильної контрольної цифри; його належність
дочірній структурі не встановлена. Інші непідтверджені номери не виправлено.

## Інтервали

Активне групування: джерело + ІПН отримувача + HS6, усі відправники разом.
Національні розширення HS зберігаються у сирому аудиті. Різні джерела
не об'єднуються автоматично, щоб не змішувати копії декларацій і різне охоплення.
Інтервал — кількість календарних днів від попереднього відмінного дня
декларування в цій групі. Для першого дня — `null`; кілька рядків за один
день мають однаковий інтервал від попереднього дня.
Це інтервал між днями декларування, а не точний час між партіями всередині дня.

## Вихід

Папка за замовчуванням: `data/local_trade_import`.

- `shipments.json`, `shipments.csv`: вісім замовлених полів.
- `row_audit.json`: початкові дані, визначення ІПН, пропуски й виключення.
- `rhythm_summary.json`: середнє, медіана та коефіцієнт варіації інтервалів.
- `run_manifest.json`: локальні шляхи, SHA-256 файлів і кількості записів.

Запуск замінює вихідні файли в заданій папці. Для збереження попереднього
результату задавайте нову папку через `--output-dir`. Вхідні дані та
довідник не редагуються. Читання виконується в пам'ять; дуже великі
вивантаження потребують окремої потокової обробки.

Перевірка на синтетичних даних не є збором реальних поставок.

```sh
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -p 'test*trade*py' -v
```
