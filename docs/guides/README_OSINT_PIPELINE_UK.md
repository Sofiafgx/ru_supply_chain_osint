# Модульний OSINT-пайплайн: сім блоків первинних даних

`osint_pipeline/` додає єдині плоскі записи для семи блоків із вашого запиту.
Наявні колектори, їхні файли та активні процеси не змінено. Повторно використано
парсери вакансій, патентів, карток ЄІС і судових списків.

## Запуск

З кореня проєкту:

```sh
PYTHONPATH=src .venv/bin/python -m osint_pipeline --manifest examples/osint_live_smoke.json \
  --output outputs/my_osint_run
```

Маніфест невеликого живого запуску запитує одну вакансію HH, одну картку Аршину,
обмежений агрегат Comtrade та одну сцену Copernicus. Це перевірка підключення,
а не тематичне дослідження підприємств або повне вивантаження реєстрів.
Для мережевого збору потрібні доступні джерела; файл не містить секретів.

Перевірка конфігурації без звернення до мережі:

```sh
PYTHONPATH=src .venv/bin/python -m osint_pipeline --manifest examples/osint_live_smoke.json --validate-only
```

Залежності для цього модуля окремо наведено в `requirements/requirements-osint-pipeline.txt`.
Використовується Python 3.9 або новіший; поточне середовище `.venv` вже має залежності.

## Результати

У каталозі `--output` створюються:

- `block_1.ndjson` … `block_7.ndjson` — сім потокових файлів з усіма запитаними полями;
- `raw/<sha256>.bin` — байти, які отримав парсер, до нормалізації;
- `raw/responses.ndjson` — час, URL, статус і checksum кожної HTTP-відповіді, включно з невдалими;
- `report.json` — результат кожного завдання, кількість записів, завершеність пагінації та помилки;
- `shipment_intervals.ndjson` — інтервали між спостережуваними датами поставок;
- `shipment_intervals.sqlite3` — накопичені доказові дати для розрахунку інтервалів.

Файли блоків дописуються, кожен рядок одразу скидається на диск. Повторний запуск
може записати повторні спостереження; для незалежного запуску задайте нову папку.
Інтервали перераховуються за накопиченими записами у цій папці. Блокування
каталогу не дозволяє двом екземплярам цього модуля писати туди одночасно.

Кожен запис має `source_url`, `input_sha256`, `collected_at`, а також `raw_file`,
`source`, `job_id`, `ingested_at` і `warnings`. SHA-256 стосується збереженого
тіла відповіді після HTTP-декодування або точних байтів імпортованого файлу.
Один checksum може стосуватися кількох записів із тієї самої відповіді.
URL картки може відрізнятися від URL API: URL фактичної відповіді збережено в
`raw/responses.ndjson`. Пошуковий ІПН ніколи не підставляється в реквізити сторони.

Відсутні значення — JSON `null`, без нулів, вигаданих дат чи ідентифікаторів.
Підтверджений нуль зберігається як 0. ІПН має 10 або 12 цифр; це перевірка
формату, а не доказ належності компанії. HS має 4–6 цифр без доповнення нулями.
Рік статті не перетворюється на 1 січня: `record_date=null`. Час події без
часового поясу не оголошується UTC. Непридатні значення позначаються у `warnings`.

Для старих локальних файлів час первинного збору може бути невідомий:
`collected_at=null`, окремо фіксується `ingested_at`. Якщо відомий час, передайте
`collected_at` у завданні. Поточний час імпорту не підміняє історичний час збору.
Тестові фікстури з `tests/` не використовуються як зібрані дані.

| 1 | `clearspending` | Пошук через публічний шлюз, картки й структуровані експорти |

| 2 | `hh`, `trudvsem` | API-пошук; окремі JSON-вакансії; HTML і експорти |
| 2 | `rostender`, `joblab`, `cznelb` | Окремі HTML-оголошення та JSON/CSV/NDJSON; для Rostender відбираються згадки сервісу/ремонту |
| 3 | `arshin` | Solr-пошук і детальна картка, структуровані експорти; HTML через явно задані селектори |
| 4 | `comtrade` | Preview API місячних агрегатів; не дані окремих декларацій |

| 5 | `google_patents`, `fips` | Повнотекстовий HTML, ST.36 XML, JSON формули/опису або готових цитат |
| 6 | `firms` | Офіційний CSV API за ключем, районом і датою; також CSV-імпорт |

Пошук реалізовано лише там, де є конкретний протокол. Універсального пошуку
для решти сайтів немає: оператор задає прямий URL чи експорт. Для платних,
закритих або динамічних сторінок можуть знадобитися доступний експорт і карта
колонок/селектори. PDF, OCR, авторизовані сесії й автоматичний аналіз змін
зображень не входять до цього модуля. Невідома HTML-структура та антибот-сторінка
фіксуються як помилка, а не як успішний порожній результат.

## Маніфести

`jobs` — непорожній масив завдань з унікальними `id`, номером `block`, назвою
`source` та одним із режимів `search`, `url`, `file`. Шляхи відносні до маніфесту.

Імпорт первинного експорту, де назви колонок відрізняються:

```json
{
  "jobs": [{
    "id": "shipment-export", "block": 4, "source": "panjiva",
    "mode": "file", "path": "shipments.csv", "format": "csv",
    "source_url": "https://panjiva.com",
    "column_map": {
      "importer_inn": "ИНН импортера",
      "importer_name": "Consignee",
      "exporter_name": "Shipper",
      "declaration_date": "Arrival date",
      "hs_code": "HS Code",
      "net_weight_kg": "Net weight (kg)",
      "customs_value_usd": "Value (USD)"
    }
  }]
}
```

Приклад конфігурації не є первинним записом. Якщо відомий URL конкретного
експорту/картки, використайте його замість домашньої сторінки. `column_map`
зв'язує запитане поле з назвою колонки або вкладеним JSON-шляхом, наприклад
`customer.inn`. `records_path` задає шлях до масиву записів усередині JSON.
Для `units_qty` потрібна колонка саме в штуках; загальна `quantity` переноситься
лише за явно опублікованої одиниці `pcs`/`pieces`/`шт` тощо. Вага брутто не
переноситься в нетто, іноземна валюта не оголошується рублями.

У режимі `url` задайте `url`, за потреби `format`, `params`, `method` та `body`
для JSON-запиту POST. У режимі `file` підтримуються `encoding`, `source_url`
та відомий `collected_at` із часовим поясом.

Для HTML джерела, структура якого не має спеціалізованого парсера, задайте
`record_selector` та `selectors`, наприклад:

```json
{
  "id": "inspection-document", "block": 7, "source": "proverki",
  "mode": "file", "path": "inspection.html", "format": "html",
  "record_selector": "article.inspection",
  "selectors": {
    "record_id": ".inspection-number",
    "company_inn": ".inspected-company .inn",
    "record_date": {"css": "time", "attribute": "datetime"},
    "supervisory_authority": ".authority",
    "raw_quote": ".act-text"
  }
}
```

Селектори в цьому прикладі слід замінити на фактичні селектори вашого документа.
Поля читаються лише всередині вузла запису; ІПН власника порталу з футера не
стає ІПН підприємства. Цитати зберігаються як текст відповідного вузла HTML
або оригінальний рядок JSON/CSV; первинні байти доступні в архіві.

## Мережева стійкість

```json
{
  "network": {
    "proxy_file": "my_proxies.txt",
    "timeout": 50, "attempts": 4, "interval": 1, "max_wait": 60
  },
  "jobs": [
    {"id": "jobs", "block": 2, "source": "hh", "mode": "search", "query": "Haas", "max_pages": 2, "page_size": 25}
  ]
}
```

Проксі задаються повними URL `http://`, `https://`, `socks5://`, по одному на
рядок. Замість файлу можна передати `network.proxies` як масив. Клієнт циклічно
змінює проксі між спробами; за заданого непорожнього пулу не переходить на пряме
з'єднання. Без проксі виконує прямі запити. Не використовує `.env` чи системні
проксі автоматично. TLS перевіряється.

Читання обмежене 50 секундами, підключення — максимум 15. Повтори виконуються
для 429, 499, усіх 5xx і транспортних помилок. Експоненційна пауза має jitter;
`Retry-After` підтримує секунди та HTTP-дату. Якщо сервер просить чекати довше
за `max_wait`, завдання припиняється зі збереженим строком очікування у звіті;
раннього повтору немає. HTTP 401/403 не повторюються. Межі сторінок задаються
явно; їх досягнення не означає повне охоплення.

NASA FIRMS: `source="firms"`, `mode="search"`, `area="west,south,east,north"`,
`day_range` 1–10, за потреби `date` та `sensor`. Ключ читається зі змінної
оточення `FIRMS_MAP_KEY` або змінної, названої в `key_env`. Ключ редагується в
URL аудиту. Реальний ключ не додавайте до маніфесту або коду.

Код завершення 0 означає відсутність помилок завдань; 2 — хоча б одне завдання
з помилкою. Уже зібрані рядки зберігаються, стан позначається `partial_error`.
Звіт оновлюється після кожного завдання.

## Межі інтерпретації

- Судові `customer_*`/`supplier_*` — відповідно позивач/відповідач, із явними
  `record_kind="court"` і `party_roles`. Це процесуальний зв'язок, не постачання.
  Окремі масиви назв і ІПН постачальників не з'єднуються навмання.
- У Comtrade основні поля окремої поставки, включно з датою декларації,
  залишаються `null`. Значення з відповіді записуються як `aggregate_*`, `period`,
  країни та прапорці оцінювання. Місяць не перетворюється на дату відвантаження.
- Інтервали рахуються лише для записів `shipment` з відомими ІПН імпортера,
  HS і датою. Дати одного дня об'єднуються; кожен інтервал містить посилання
  на джерела та checksum обох кінцевих спостережень. Це інтервали між видимими
  датами, без висновків про запас або регулярність повної історії.
- Патенти: числове значення каналів зберігається лише за однозначної згадки;
  кратність компонентів — лише за явного числового зв'язку з каналом. Окремі
  компоненти мають окремі рядки й `component_name`. Кількість каналів сама по
  собі не доводить кількість мікросхем.
- FIRMS: координати стосуються пікселя виявлення, що явно позначено;
  ідентифікація підприємства, пошкодження та відновлення не припускаються.
  Copernicus повертає метадані сцени: її час у `observation_time`, а `t_event`,
  `damage_type` і `t_recovery` — `null` без окремого доказу.
- Повідомлення дослідницьких і новинних сайтів зберігають походження й попередження
  про потребу перевірки. Вони не стають автоматично первинною митною декларацією
  чи результатом аналізу супутникових зображень.

## Перевірка

```sh
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -p 'test_osint_pipeline.py' -v
```

Перевірено NULL, нулі, одиниці, ролі сторін, цитати, відсутність вигаданого часу,
архів первинних байтів, ротацію, коди повторів, `Retry-After`, інтервали та CLI.
Окремо пройшли наявні тести джерел, патентів і вакансій.

Живий запуск 10 жовтня 2026 року: `outputs/osint_pipeline_smoke_20261010/report.json`.
Отримано одну реальну сцену Copernicus. HH і Comtrade повернули HTTP 403;
Аршин — помилку підключення. Порожні файли відповідних блоків не є доказом
відсутності фактів. Живий доступ до всіх інших джерел цим запуском не перевірявся.

Офіційні протоколи:
[HH](https://api.hh.ru/openapi/redoc),
[FIRMS](https://firms.modaps.eosdis.nasa.gov/content/academy/data_api/firms_api_use.html),
[Copernicus OData](https://documentation.dataspace.copernicus.eu/APIs/OData.html).
