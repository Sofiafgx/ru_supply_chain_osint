# Пошук згадок імпортного обладнання

`src/cnc_trace_search.py` шукає вакансії операторів/наладчиків та тендери на ремонт,
сервіс і технічне обслуговування. За замовчуванням використовує ІПН
2128700223, 1804002498, 6612001460, 6444009038.

```sh
.venv/bin/python src/cnc_trace_search.py --output data/cnc_traces/records.json
```

Залежності вже є у `requirements.txt`: `httpx`, `beautifulsoup4`.
Запуск з окремого середовища: `python3 -m pip install httpx beautifulsoup4`.
Скрипт використовує наявні модулі `parsers`, тому зберігайте його у цьому проєкті.

## Доступ і охоплення

- **trudvsem.ru:** офіційний API `/api/v1/vacancies/company/inn/{inn}`,
  пагінація `offset`/`limit`. ІПН підтверджений областю запиту; явний
  конфлікт ІПН у відповіді відхиляється.
- **hh.ru:** офіційний API `/vacancies?employer_id=...`, потім детальні картки.
  Передайте `--hh-employers hh_employers.json`. Файл має формат
  `{"2128700223": [{"employer_id": "ПІДТВЕРДЖЕНИЙ_ЧИСЛОВИЙ_ID", "evidence_url": "URL_ДЖЕРЕЛА_ВІДПОВІДНОСТІ_ІПН"}]}`.
  Замініть позначки реальними значеннями. Ця відповідність є зовнішнім
  підтвердженим вхідним даним: скрипт не верифікує вміст evidence_url.
  Пошук ІПН у тексті вакансії або збіг назви компанії не доводять відповідність
  роботодавця. Без файлу цей етап фіксує помилку і продовжує інші джерела.
- **rostender.info:** виявлення кандидатів через публічну RSS-видачу Bing із
  запитом за ІПН, далі читання окремих карток. Це допоміжний неповний спосіб,
  не офіційний API РосТендер; RSS може бути недоступною або змінитися.
  Альтернатива: `--rostender-seeds rostender_seeds.json`, формат
  `{"2128700223": ["https://rostender.info/ШЛЯХ_ДО_КАРТКИ"]}`.
  ІПН має бути явно підписаний у блоці замовника картки. Використовуються
  селектори buyer/customer, tender-customer, customer-info,
  tender-info__customer; якщо верстка відрізняється або блок прихований,
  картка відхиляється як непідтверджена. Самого ІПН у пошуковій видачі недостатньо.
  При перевірці 10.10.2026 прямий HTTP-запит до РосТендер завершився тайм-аутом;
  живе збирання з нього не підтверджено.

Запити послідовні, з паузою, тайм-аутом і перевіркою TLS. HTML антибот-перевірок
не приймається за оголошення. Скрипт не обходить CAPTCHA або авторизацію.
`--max-pages`, `--delay`, `--timeout`, `--sources` керують запуском.
Охоплення обмежене поточними публічними вакансіями та індексованими/заданими
тендерами; історичної повноти немає. Звіти позначають обмеження пагінації.

## Парсинг і вихід

Підтримуються DMG Mori, Haas, Fanuc, Sodick, Heidenhain, Siemens, Doosan,
Mazak, Hermle, Studer, кириличні варіанти, Siemens 840D і загальні фрази
«токарный ЧПУ», «5-осевой», «фрезерный обрабатывающий центр».
Модель визначається regex для відомої сім'ї одразу після бренду;
невідома модель — `null`. Бренд без контексту ЧПУ/верстата відхиляється.
Загальні фрази зберігаються з `cnc_brand: null`, `cnc_model: null`.
Контекст — речення або пункт переліку, відокремлений крапкою з комою.

JSON містить один об'єкт на компанію й оголошення:

```json
{
  "company_inn": "2128700223",
  "detected_cnc_list": [{
    "company_inn": "2128700223",
    "source_site": "hh.ru",
    "record_id": "123",
    "record_date": "2026-10-08",
    "text_fragment": "Работа на Haas VF-3.",
    "cnc_brand": "Haas",
    "cnc_model": "VF-3",
    "is_sanctioned_equipment": null,
    "sanctions_basis": null,
    "sanctions_status": "not_established"
  }],
  "evidence_url": "https://hh.ru/vacancy/123",
  "timestamp": "2026-10-10T00:00:00+00:00"
}
```

Це **синтетичний приклад**, не знайдена вакансія. Якщо сайт не дає ID,
скрипт записує явно позначений `url_sha256:...`. Дата — дата публікації,
невідома дата — `null`; timestamp — UTC момент запуску.

Поруч записуються `.report.json` з помилками/відхиленнями та каталог `_raw`
зі знімками відповідей. Код завершення 2 означає помилку хоча б одного
етапу; часткові результати збережені. Порожній JSON не доводить відсутності
обладнання. Повторний запуск замінює результат; для історії задавайте новий шлях.
Згадка марки в досвіді кандидата не доводить володіння верстатом.

## Санкційні правила

Назва бренду сама по собі не встановлює юридичний статус обладнання.
Обмеження можуть залежати від моделі, характеристик, коду товару,
юрисдикції, дати, одержувача та операції. Тому вбудованого списку
«санкційних брендів» із вигаданими статусами немає.

`--sanctions-rules sanctions_rules.json` приймає масив перевірених правил:
`brand`, необов'язковий `model_regex`, `jurisdiction` (`EU`/`US`),
`basis_url`, `checked_at` (ISO дата). Regex моделі перевіряється без
урахування регістру. Відсутній `model_regex` означає усі згадки бренду.
При збігу ставиться **is_sanctioned_equipment: true**, збережене повне
правило й статус `configured_rule_match_requires_legal_review`.
Це автоматичний скринінг за вашим правилом, не юридичний висновок.
Без збігу — `null`, а не твердження про відсутність обмежень.

Офіційні джерела для перевірки правил:
- https://finance.ec.europa.eu/news/eu-adopts-17th-package-sanctions-against-russia-2025-05-20_en
- https://www.bis.gov/regulations/ear/746
- https://api.hh.ru/openapi/redoc
- https://web-szn-demo01.k8s.trudvsem.ru/opendata/api

## Відтворювана обробка збережених даних

```sh
.venv/bin/python src/cnc_trace_search.py --offline notices.json --output data/cnc_traces/offline.json
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -p test_cnc_trace_search.py -v
```

`notices.json` — масив записів з `source_site` (`hh`, `trudvsem`, `rostender`
або домен), `company_tax_id`, `title`, `description`, `source_url`,
необов'язковими `record_id`, `posting_date`. У цьому режимі відповідність
ІПН є відповідальністю підготовленого вхідного набору.
