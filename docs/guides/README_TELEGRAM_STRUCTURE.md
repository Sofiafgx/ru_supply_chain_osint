# Структурування Telegram для дослідження стійкості

Додано окрему обробку вже зібраного архіву. Вона читає джерело без змін,
зберігає результати в `data/telegram_structured/structured.sqlite3` і повторно
обробляє лише змінені дописи або дописи після зміни версії правил.
Обробка пакетами дозволяє основному вебзбору продовжувати роботу.

## Результати

- `structured_posts.jsonl`: релевантні за словниковими правилами дописи,
  текст, походження, контрольна сума та всі витягнуті згадки.
- `events.csv`: речення/абзаци з можливими подіями виробництва, поставок,
  порушень роботи, відновлення, запасів або споживання.
- `entities.csv`: назви організацій із явним контекстом, бренди, явно
  зазначені ІНН/ОГРН/HS, артикули та класи обладнання.
- `dates.csv`: окремі згадки дат і попередження про неоднозначність.
- `summary.json`: кількість опрацьованих дописів, згадок і кандидатів.

Наявність промислового слова не доводить належності суб'єкта до ВПК РФ.
`russia_mentioned` та `defence_industry_mentioned` означають лише згадку в тексті.
Відбір широкий: можуть потрапити інші країни, галузі й історичні приклади.
Це перший словниковий прохід, не вичерпне розпізнавання всіх подій чи назв.

Кожна згадка має позицію в тексті. Дата публікації не замінює дату події.
Дата без року не отримує вигаданий рік. Відносні дати інтерпретуються від
дати публікації у Europe/Kyiv, але потребують перевірки: «сьогодні» може
описувати сучасний стан, а не окрему подію; пересланий текст може бути старішим.
Числа і одиниці зберігаються як згадки без автоматичного призначення ролі
«запас», «добове споживання» чи «фактична потужність».

ІНН береться лише з явно підписаного поля; контрольна сума перевіряє формат,
а не факт існування юридичної особи. Схожі назви не об'єднуються, назва й ІНН
не прив'язуються автоматично. HS-коди не виводяться з класу обладнання.
Речення позначаються за наявністю заперечення або мови планів; це сигнали
для перегляду, не повний семантичний аналіз.

Усі твердження мають статус `unverified_channel_claim`. Перепублікації
залишаються окремими доказами походження з однаковою контрольною сумою тексту;
вони не є незалежним підтвердженням. Первинний архів не змінюється.

## Вхідні дані для метрик

**TTR**: потрібні перевірена тотожність підприємства/процесу, дата порушення,
дата повернення до 100% визначеної доаварійної потужності та підтвердження,
що обидві дати стосуються одного порушення. Повідомлення про початок ремонту
або частковий запуск не доводить повного відновлення.

**TTS**: у погодженому базовому сценарії використовуємо
`available_S_safe / BOM_daily_component_consumption` для одного компонента,
однакових одиниць і визначеної дати залишку, за відсутності нових надходжень.
Буфер має бути фізично доступним для споживання; недоступний резерв до нього
не додається. Добова норма визначається BOM і виробничим планом. Це базовий
показник запасу; TTS мережі з альтернативними постачальниками й запасами
на інших рівнях потребує окремої моделі. Інтервал між поставками не є TTS.

**REI**: спочатку необхідно погодити методику, модель втрат і мережу.
Попередня формула з `analytics/proxy_model.py` не застосовується до дописів.
Значення TTR/TTS/REI залишаються `null`, а потрібні входи перелічені
в `metric_inputs`. Жодний кандидат не допускається до розрахунку автоматично.

Методологічні джерела:
[MIT про TTR і TTS](https://news.mit.edu/2022/companies-use-mit-research-identify-respond-supply-chain-risks-0615),
[MIT про REI](https://news.mit.edu/2014/mit-professor-risk-exposure-index-used-un-disaster-risk-reduction).

## Запуск агентом

`src/telegram_structure_cli.py` читає типовий вебархів. Повторюваний параметр
`--source` дозволяє додати SQLite MTProto-архів; ці джерела залишаються
окремими за походженням. Результати експортуються при завершенні проходу.
Стан є знімком опрацьованого архіву, не автоматичним постійним оновленням.

Окремий [двокроковий відбір ВПК РФ](README_TELEGRAM_FILTER.md) перевіряє
повний локальний архів за довідником суб'єктів і контекстними мовними моделями.

## MTProto та коментарі

Основний MTProto-збирач уже підтримує доступну історію, повторне сканування
й завантаження медіа через `download_media`. Додано `comments` і опцію
`--collect-comments` у `src/telegram_cli.py` для доступних коментарів до вже
архівованих дописів, які позначені Telegram як дописи з обговоренням.

Для кожного допису коментарі проходяться окремо до верхньої межі поточного
проходу. Коментар і курсор фіксуються разом, повідомлення мають ID групи
обговорення, ID батьківського каналу/допису та URL. Зміна групи використовує
окремий курсор її повідомлень. Одна недоступна гілка не зупиняє інші.
Коментарі експортуються окремо в `comments.jsonl`/`comments.csv`, не змішуються
з дописами й наразі не входять у структурований аналіз.
Стан `complete_pass` означає завершення доступного проходу, не дату створення.

Це використання офіційного протоколу Telegram через бібліотеку Telethon,
а не офіційний застосунок Telegram. Потрібні власні API ID/API hash і
авторизована сесія технічного користувацького акаунта; бот-токен не замінює її.
Автоматичної реєстрації акаунта або приєднання до приватних груп немає.
Медіа з API є доступною серверною версією файла; це не гарантія оригіналу до
стиснення Telegram. Видалені й недоступні повідомлення не відновлюються.

[Telegram про групи обговорення](https://core.telegram.org/api/discussion),
[Telethon про iter_messages](https://docs.telethon.dev/en/stable/modules/client.html#telethon.client.messages.MessageMethods.iter_messages).
