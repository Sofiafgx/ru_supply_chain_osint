# Industrial Labor & Equipment Tracker

Окремий парсер відкритих вакансій ЧПУ й оголошень про ремонт/ТО.
Початкова вибірка: [результати](../../data/industrial_20261009/records.json),
[докази](../../data/industrial_20261009/records.evidence.json),
[звіт про охоплення](../../data/industrial_20261009/REPORT_UK.md).

Вихідний JSON містить рівно сім запитаних полів. Невідомі ІПН та дати —
`null`. `equipment_brand_model` — рядок; декілька згадок розділено `;`.
Оригінальне написання, контекст, назва роботодавця, тип обладнання,
походження файлу й попередження зберігаються у сусідньому `.evidence.json`.

Підтримуються Haas, DMG Mori, Fanuc, Siemens, Sodick і Doosan та обмежені сімейства
їхніх моделей. Назва моделі не виводиться з сусіднього довільного слова.
Окремі згадки марки без моделі теж зберігаються. Fanuc та Siemens
позначаються як система ЧПУ/компонент, а не автоматично як виробник верстата.
Неявні моделі без назви марки, непрочитані вкладення та непідтримувані
сімейства моделей можуть бути пропущені; для них потрібна перевірка.

## Джерела та доступ

| Джерело | Режими |
|---|---|
| ФКЦ ОПК / `fkc` | Публічний список і картки JSON; `--discover`; локальні JSON |
| HeadHunter / `hh` | Офіційний API пошуку та карток; `--discover`; локальний JSON API або HTML JobPosting |
| JobLab / `joblab` | Пряма HTML-картка вакансії або нормалізований JSON |
| CZNELB / `cznelb` | Пряма HTML-картка, її власний опис без рекомендацій; JSON |
| РосТендер / `rostender` | Пряма HTML-картка тендера або JSON із назвою й описом |
| ТрудВсем / `trudvsem` | Локальний офіційний JSON API або нормалізований JSON; HTML JobPosting |
| Indparks / `indparks` | Контекст підприємств; не створює записи вакансій чи тендерів |

Автоматичне виявлення карток реалізовано для ФКЦ та HH. Для інших порталів
потрібні конкретні URL або збережені оголошення. Вебпошук використано для
початкової перевірки джерел; він не є частиною CLI. Знайдені лише в індексі
оголошення зберігаються окремо як leads і не додаються до перевіреної вибірки.
Парсер не розв'язує CAPTCHA й не відкриває платні документи. За явно заданим
`--proxy-file` підтримується обмежена ротація проксі з перевіркою TLS.
Частина полів РосТендер прихована; ІПН оператора порталу з футера ігнорується.

## Використання

```sh
.venv/bin/python src/industrial_cli.py fkc --discover --limit 100 --output data/industrial_new/fkc.json
.venv/bin/python src/industrial_cli.py hh --discover --query 'ЧПУ Haas' --limit 50 --output data/industrial_new/hh.json
.venv/bin/python src/industrial_cli.py cznelb --url https://cznelb.ru/vacancy/329853419 --output data/industrial_new/cz.json
.venv/bin/python src/industrial_cli.py joblab --input exports/job.html --source-url https://joblab.ru/vacancy/13436122 --output data/industrial_new/joblab.json
.venv/bin/python src/industrial_cli.py joblab --url https://joblab.ru/vacancy/13436122 --proxy-file config/private/proxies.txt --proxy-offset 250 --proxy-attempts 4 --output data/industrial_new/joblab_proxy.json
```

Повторювані `--input` і `--url` дозволяють обробити декілька карток одного
джерела. HTML потребує прямого URL картки. JSON/JSONL для всіх джерел приймає
об'єкт або масив з полями `title`, `description`, `source_url`,
`company_name`, `company_tax_id`, `posting_date`, `closure_date`,
`application_deadline`, `archived`; останні поля необов'язкові.
Також підтримуються оригінальні JSON картки HH та ФКЦ.

Клієнт зберігає завантажені сторінки, робить паузи, перевіряє TLS і припиняє
автоматичне виявлення на помилці доступу. Вивід: JSON, `.evidence.json`,
`.report.json`; мережеві знімки — у `<назва>_raw/`. За часткових помилок
непорожній результат є частковою вибіркою; дивіться аудит. Якщо всі запити
завершились помилкою, попередній JSON не перезаписується. Успішний запуск
замінює файл; для історії задавайте новий каталог.

## Дати й інтерпретація

`posting_date` у ФКЦ береться з `PublicationDate`, а не дати оновлення.
Мілісекунди ASP.NET перетворюються за московським часом джерела.
Інші джерела: явне поле API, `datePosted` або підписана дата картки.
Відносні дати на кшталт «3 дня назад» не перетворюються на точні.

`closure_date` заповнюється явною датою фактичного закриття/архівування
у вхідному записі або явно вказаною датою «в архиве с ...» у заголовку картки HH.
`archived=true`, прихованість, `validThrough`, дедлайн
заявок та зникнення картки не встановлюють дату закриття. Дедлайн зберігається
окремо у доказах. Автоматичного історичного моніторингу не створено.

`capacity_expansion` — задана користувачем категорія для вакансій операторів
і наладчиків. Вона може відображати заміну працівника або повторне розміщення,
тому не підтверджує розширення потужностей. `equipment_maintenance` —
оголошення про ремонт/ТО або вакансія з ремонтом у назві. Звичайне щоденне
обслуговування в описі вакансії оператора не змінює її категорії.

Згадка досвіду роботи з маркою може бути лише вимогою до кандидата, а не
доказом наявності такого верстата на підприємстві. Постачання обладнання,
запчастин і загальні профілі компаній не вважаються ремонтними замовленнями.
Відбір ФКЦ за назвою посади може пропустити оголошення з нетиповими назвами.

## Допарсинг

Результати повторної перевірки — у `data/industrial_20261009_followup/`.
`records.json` об'єднує початкову й нову вибірки; `new_records.json` містить
лише нові записи. `src/industrial_followup_build.py` відтворює їх зі знімків.

РосТендер також читає окремі картки поточного списку категорії: назву,
опубліковану дату й фактичне посилання на тендер. У доказах вони позначені
`live_listing_card; detail_not_verified`. Це дозволяє відрізняти прочитану
картку списку від детальної сторінки, яка може бути недоступна. Дедлайн
заявок лишається окремим полем доказів, а дата закриття — `null`.

Ротація обмежена `--proxy-attempts`; `--proxy-offset` задає початкову позицію
в пулі. Невдалі маршрути не скидаються автоматично, щоб уникнути зациклення.
Журнал містить лише номер маршруту, тип помилки та HTTP-статус; адреси й
паролі проксі не записуються. У допарсингу робочою була позиція 250 у
наявному файлі; її доступність у майбутньому не гарантується.

## Перевірка

Окремий експорт за схемою `company_inn`, `cnc_brand`, `cnc_model`,
`source_url`: [CSV](../../data/cnc_inventory_20261010/records.csv),
[JSON](../../data/cnc_inventory_20261010/records.json),
[охоплення й обмеження](../../data/cnc_inventory_20261010/REPORT_UK.md).
Відтворюється через `src/cnc_inventory_export.py`; оцінка TTR автоматично
не присвоюється.

```sh
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -p 'test_industrial_labor.py' -v
```

Тести перевіряють моделі й марки без моделі, відкидання екскаваторів,
ізоляцію рекомендацій, дати публікації й закриття, відсутній ІПН,
відмінність закупівлі запчастин від ремонтних послуг і JSON-LD.
