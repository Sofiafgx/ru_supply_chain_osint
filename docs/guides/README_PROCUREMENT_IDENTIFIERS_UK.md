# Ідентифікатори закупівель у контрактах

Поля `notif_num` (номер повідомлення про закупівлю) і `purchase_code` (код закупівлі) зберігаються як текст у нормалізованому записі контракту, повному CSV та компактних CSV. Початкові нулі не видаляються. Порожнє поле лишається порожнім; номер контракту не підставляється замість номера закупівлі.

Ці поля є ідентифікаторами закупівлі, а не реквізитами постачальника. Їх додавання не заповнює ІПН, назву або статус виконання договору.

Для вже зібраного основного архіву використовується `src/backfill_procurement_identifiers.py`. Він читає лише локальні сирі відповіді, перевіряє SHA-256 і шукає точний номер контракту в його власному файлі походження. Неузгоджені номери, контрольні суми або наявні значення спричиняють помилку. Відомості із сусіднього контракту не переносяться.

Перед оновленням SQLite зберігається резервна копія бази. Кожний змінений CSV і JSONL також має резервну копію. Зміна бази виконується транзакцією; файли замінюються окремо після їх повного запису. У разі збою експорту база може вже містити нові поля; після усунення причини обробку можна повторити з новою папкою результатів.

```sh
.venv/bin/python src/backfill_procurement_identifiers.py \
  --archive data/collection_20261008 \
  --output outputs/procurement_identifiers_20261010 \
  --extra-csv data/processed/procurement/matched_contracts_summary.csv
```

Папка `--output` має бути новою, щоб не перезаписати резервні копії. `audit.json` містить кількості відновлених полів, у тому числі серед контрактів без постачальника, кількість рядків CSV і результат перевірки SQLite. Сирі відповіді не змінюються. Інші незалежні архіви та раніше створені аналітичні похідні цією командою не оновлюються.
