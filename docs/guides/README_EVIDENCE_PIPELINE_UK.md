# Конвеєр доказових спостережень і метрик

Реалізація використовує наявні колектори, SQLite і знімки їхніх результатів.
Знімок не запускає нових мережевих запитів та не змінює файли активних колекторів.

## Запуск

```sh
.venv/bin/python src/evidence_snapshot.py
```

Результати в `outputs/evidence_pipeline/`:

- `evidence.sqlite3` — первинні спостереження, нормалізовані таблиці та зв'язки;
- `reports/status/coverage.json` — три неперетинні категорії виконаних запитів;
- `evidence_limits.json` — доказові ребра, сценарії, кандидати й прогалини;
- `manifest.json` та копії JSONL — відтворювані вхідні дані знімка.

`src/run_data_update.py` створює цей знімок після завершення колекторів.
Уже запущений процес використовує завантажену раніше версію програми;
зміни набудуть чинності в наступному запуску.

Для затвердженого переліку використовуйте JSON-масив рівно 20 різних ІПН:

```sh
.venv/bin/python src/evidence_snapshot.py --pilot-file approved_pilots.json
```

Перелік не знайдено в поточному проєкті. Наявні набори з 4, 6 і 10 суб'єктів
не розширюються автоматично, ІПН з іншими контрольними сумами не підміняються.
Поки список відсутній, активація взаємних контрактних і судових ребер заблокована.
Знімок імпортує наявні архівні записи як спостереження, а не підтверджує їхню
належність до ще не заданого пілотного охоплення.

## Довільні входи й результати запитів

```sh
.venv/bin/python src/evidence_pipeline.py --manifest path/to/manifest.json \
  --database outputs/custom/evidence.sqlite3 --output outputs/custom
```

Формат маніфесту:

```json
{
  "pilot_inns": [],
  "inputs": [
    {"path": "contracts.jsonl", "kind": "contract"},
    {"path": "stock.jsonl", "kind": "inventory"}
  ],
  "queries": [
    {"query_id": "source:scope", "source": "registry", "category": "no_result"}
  ],
  "pending_queries": []
}
```

Шляхи відносні до маніфесту. Доступні типи: `contract`, `court`, `equipment`,
`trade`, `inventory`, `consumption`, `radar`, `scenario`.
`queries` містить явні результати запитів, а не висновок із відсутності рядків.
Знайдені відповіді позначаються `found`, успішні порожні — `no_result`,
помилки доступу чи вичерпаний технічний ліміт — `technical_access_unavailable`.
Причина зберігається в деталях; ліміт бюджету не означає блокування сервером.
Запити, які ще не виконані, залишаються в `pending_queries` поза цими категоріями;
`query_scope_complete=false` явно позначає неповне охоплення.

## Походження й нормалізація

`observations` має `input_sha256`, `collected_at`, `source_url`, окремий
`ingested_at`, шлях та номер рядка. Контрольна сума імпортера стосується саме
вхідного JSONL-файлу; первинний checksum колектора додатково збережено в payload.
Історичний час збору не замінюється часом імпорту: відсутнє значення — SQL NULL
із записом у звіті прогалин. Час із часовим поясом нормалізується до UTC.
Це свідомий виняток для неповних старих архівів; їхні записи без необхідних
атрибутів не активують граф.

Таблиці `contracts`, `contract_evidence`, `court_evidence`, `monthly_trade`,
`equipment`, `inventory`, `consumption`, `metrics` посилаються на спостереження.
Атрибути аудиту читаються через цей зовнішній ключ; `graph_edges` вже містить їх.
Контракт має ключ `(customer_inn, supplier_inn, contract_id)`. Різні номери
угод та конфліктні версії доказів зберігаються окремо. Повторний імпорт того
самого файлу з тими самими метаданими не дублює спостереження.

Для активації ребра потрібні: перевірені ІПН обох пілотів, різні сторони,
непорожній номер, джерело, час і `verified=true`. Для суду потрібні саме
`plaintiff_inn` та `respondent_inn`. `verified` — атестація адаптера або
оператора щодо реквізитів у джерелі, не незалежна гарантія істинності джерела.
Належність до холдингу й агреговані торговельні ряди не активують ребер.
Судове ребро доводить процесуальний зв'язок і не визначає напрям постачання.

## Колектори

- Аршин: стандартна сторінка `rows=100`, поворот через наявний пул проксі,
  обробка 499/429/502/503/504 та транспортних помилок з backoff. Читання
  обмежене 50 секундами в CLI. Усі отримані HTTP-відповіді додаються до
  `.responses.jsonl` зі `flush`; точні байти зберігаються як Base64 із checksum.
  Збіги містять checksum збереженої картки, UTC і URL.
- Comtrade: офіційний Preview API, місячні HS6-ряди та локальний SQLite-кеш.
  `Retry-After` підтримує секунди й HTTP-дату; довгі паузи зберігаються в кеші
  для наступного запуску. Raw-відповіді архівуються з дозаписом, кешовані
  масиви — у `.evidence`; історичний час при повторному імпорті не оновлюється.
  Обрізана відповідь не стає повним рядом.
- Контракти/суд: онлайн-колектор записує checksum, UTC, URL та статус перевірки
  реквізитів; HTTP-архів має точні байти й час. Локальні CSV не мають
  вигаданого часу збору. Batch-фільтр отримує затверджений список через
  `src/contract_links_async.py --inns ...`; новий ledger додатково перевіряє
  взаємну належність до пілотів і доказові реквізити.

Живий мережевий доступ і повноту збору не можна встановити лише модульними
тестами. Поточний знімок чесно зберігає фактичні помилки та невиконані запити.

## Метрики

`analytics/resilience.py`:

- `tts`: `S_safe / D_daily` у днях, тільки за `verified=true`, однакової
  фізичної одиниці запасу й щоденного попиту та додатного попиту. Нульовий
  підтверджений запас дає 0; невідомий запас — NULL. Типові 30 днів вилучено.
- `r_kj`: NULL без перевіреної норми та її одиниці; констант немає.
- Торгівля: `external_logistics_cycle`, `tts_days=null`. Місячні піки дають
  інтервал між місячними агрегатами; дати окремих великих відвантажень
  потребують окремих транспортних записів і не відтворюються з Comtrade.
- Радар: `ttr_radar_candidate` з `t_prev` і `t_observed`,
  `confirms_production_recovery=false`. Радарний модуль також записує ці поля
  поруч із попередніми сумісними полями.
- `loss_scenario`: явний інтервал `duration_days`, `daily_loss`, `max_loss`,
  одиниця випуску й текст припущення. Тип `scenario_type` має бути
  `structural_restoration` або `technological_cycle`. Межі втрат і REI
  рахуються окремо; REI не обрізається штучно до 1. Без заданої втрати
  результат NULL. Жодного сценарного строку за замовчуванням немає.
- `myerson`: точне значення Шеплі для гри, обмеженої зв'язністю графа;
  цінність коаліції — сума цінностей її компонент. Потрібна явна функція
  `v(S)` із `v(empty)=0`. Підтверджені ребра можна отримати з `graph_edges`.
  До 20 гравців, експоненційна складність. У поточному звіті значення NULL,
  бо функцію коаліції, одиниці та часовий горизонт не задано.

Старий `SupplyChainProxyModel` більше не трактує імпорт як TTS і не підставляє
9/1,5 місяця для TTR. Його коефіцієнти коаліції — лише явно заданий сценарій.

## Перевірка

```sh
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -p 'test_evidence_pipeline.py'
```

Тести перевіряють збереження повторних угод, версій і NULL, відхилення
непідтверджених ребер, транзакційний rollback, UTC, точність HTTP-архіву,
неперетинність охоплення, одиниці TTS, інтервали сценаріїв і графове обмеження
Myerson. Наявні тести колекторів також перевірено після змін.
